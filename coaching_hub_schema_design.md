# Coaching Hub Database Schema Design

Based on the prompt requirements and the existing SavvyOS schema, here is the design for the new Coaching Hub tables. The design strictly adheres to the requirement of not duplicating existing data (goals, transactions, contacts, users, markets) and instead creates new entities that link to the existing sources of truth.

## Coaching Profiles

The `coaching_profiles` table establishes a one-to-one relationship with the `users` table for users with the 'agent' role. It serves as the central repository for an agent's high-level coaching state, performance status, and current development priorities.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `id` | int | Primary key, auto-incrementing. |
| `agentId` | int | Foreign key referencing `users.id`. |
| `coachOfRecordId` | int | Foreign key referencing `users.id` for the primary coach. |
| `performanceStatus` | enum | 'Launch', 'Red', 'Yellow', 'Green', 'Elite'. Defaults to 'Launch'. |
| `marketProtectionStatus` | enum | 'Protected', 'Conditional', 'Open for Additional Coverage', 'Recruiting Active', 'Exit Pending', 'Unassigned', 'Leadership Review'. |
| `retentionRiskStatus` | enum | 'Low', 'Watch', 'Elevated', 'Critical'. |
| `currentPrimaryDiagnosis` | enum | 'Commitment', 'Capability', 'Cadence', 'Capacity', or null. |
| `currentDevelopmentPriority` | text | A brief description of the agent's current primary focus area. |
| `nextSessionCoachId` | int | Foreign key referencing `users.id` for the coach scheduled for the next session. |
| `nextSessionDate` | timestamp | The scheduled date and time for the next coaching session. |
| `createdAt` | timestamp | Record creation timestamp. |
| `updatedAt` | timestamp | Record last update timestamp. |

## Coaching Sessions

The `coaching_sessions` table records both scheduled upcoming sessions and the historical log of completed coaching sessions. It captures the scheduling details, raw notes, media assets, and the resulting AI-processed summaries and diagnoses.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `id` | int | Primary key, auto-incrementing. |
| `agentId` | int | Foreign key referencing `users.id`. |
| `coachOfRecordId` | int | Foreign key referencing `users.id` at the time of the session. |
| `scheduledCoachId` | int | Foreign key referencing `users.id` for the coach intended to run the session. |
| `actualCoachId` | int | Foreign key referencing `users.id` for the coach who actually conducted the session (null until started). |
| `sessionDate` | timestamp | The date and time of the session. |
| `sessionType` | varchar | E.g., 'Standard COACH', 'Pipeline and Performance', 'New-Agent Launch Session'. |
| `status` | enum | 'Scheduled', 'In Progress', 'Completed', 'Canceled', 'No Show'. |
| `durationMinutes` | int | The length of the session in minutes. |
| `meetingLink` | varchar | Optional URL for video conferencing. |
| `reasonForSession` | text | Brief context or required preparation notes. |
| `sourceNotes` | text | Raw typed or pasted notes from the session. |
| `recordingFileUrl` | text | S3 URL to the uploaded audio/video recording. |
| `recordingFileKey` | varchar | S3 object key for the recording file. |
| `transcript` | text | The full text transcript of the session. |
| `aiSummary` | text | The structured summary generated by AI. |
| `aiProcessingStatus` | enum | 'Pending', 'Processing', 'Completed', 'Failed'. |
| `isSummaryApproved` | boolean | Indicates whether a human coach has reviewed and approved the AI summary. |
| `primaryDiagnosis` | enum | The Four-C diagnosis resulting from the session. |
| `secondaryDiagnosis` | enum | An optional secondary Four-C diagnosis. |
| `diagnosisEvidence` | text | Supporting context for the selected diagnosis. |
| `createdAt` | timestamp | Record creation timestamp. |
| `updatedAt` | timestamp | Record last update timestamp. |

## Coaching Commitments

The `coaching_commitments` table stores the specific, measurable action items generated from coaching sessions. These commitments drive accountability and are linked back to the originating session and existing organizational goals.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `id` | int | Primary key, auto-incrementing. |
| `agentId` | int | Foreign key referencing `users.id`. |
| `sessionId` | int | Foreign key referencing `coaching_sessions.id`. |
| `description` | text | The specific action the agent or coach committed to performing. |
| `ownerId` | int | Foreign key referencing `users.id` indicating who is responsible for completion. |
| `createdById` | int | Foreign key referencing `users.id` indicating who created the record. |
| `dueDate` | timestamp | The deadline for the commitment. |
| `expectedResult` | text | The defined outcome that constitutes completion. |
| `relatedGoalId` | int | Foreign key referencing `agent_goals.id`. |
| `relatedMetric` | varchar | The specific metric this commitment aims to improve. |
| `completionEvidence` | text | Notes or links demonstrating that the commitment was met. |
| `status` | enum | 'AI Suggested', 'Not Started', 'In Progress', 'Submitted for Verification', 'Completed', 'Partially Completed', 'Missed', 'Waived', 'No Longer Relevant'. |
| `completedDate` | timestamp | When the commitment was marked complete. |
| `coachVerificationStatus` | enum | 'Pending', 'Verified', 'Rejected'. |
| `visibilityLabel` | enum | 'Agent Visible', 'Internal'. |
| `consequence` | text | The agreed-upon consequence if the commitment is missed. |
| `isAiExtracted` | boolean | Indicates if the commitment was automatically suggested by the AI processing layer. |
| `aiConfidence` | varchar | The AI's confidence level in the extracted commitment. |
| `isRepeated` | boolean | Flag indicating if this commitment has been repeatedly missed and rolled forward. |
| `createdAt` | timestamp | Record creation timestamp. |
| `updatedAt` | timestamp | Record last update timestamp. |

## Performance Resets

The `performance_resets` table manages formal 30-day intervention plans for underperforming agents. It captures the current reality, the specific requirements for recovery, and the scheduled checkpoints.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `id` | int | Primary key, auto-incrementing. |
| `agentId` | int | Foreign key referencing `users.id`. |
| `coachOfRecordId` | int | Foreign key referencing `users.id`. |
| `status` | enum | 'Draft', 'Pending Review', 'Active', 'Improving', 'Recovered', 'Extension Requested', 'Extended', 'Coach-Out Recommended', 'Exited', 'Canceled'. |
| `startDate` | timestamp | The beginning of the 30-day reset period. |
| `endDate` | timestamp | The scheduled conclusion of the reset period. |
| `requiredStandard` | text | The minimum performance standard the agent must achieve. |
| `currentResult` | text | The agent's performance metrics at the start of the reset. |
| `goalGap` | text | The quantitative difference between current results and required standards. |
| `evidence` | text | Supporting data justifying the necessity of the reset plan. |
| `consequence` | text | The communicated outcome if the reset plan fails. |
| `createdAt` | timestamp | Record creation timestamp. |
| `updatedAt` | timestamp | Record last update timestamp. |

### Performance Reset Requirements

The `performance_reset_requirements` table stores the three to five specific, measurable actions the agent must complete during their reset period.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `id` | int | Primary key, auto-incrementing. |
| `resetId` | int | Foreign key referencing `performance_resets.id`. |
| `description` | text | The specific requirement. |
| `status` | enum | 'Pending', 'Met', 'Missed'. |
| `createdAt` | timestamp | Record creation timestamp. |

### Performance Reset Checkpoints

The `performance_reset_checkpoints` table schedules and records the required check-in meetings (e.g., weekly, Day 14, Day 30) during a reset plan.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `id` | int | Primary key, auto-incrementing. |
| `resetId` | int | Foreign key referencing `performance_resets.id`. |
| `checkpointDate` | timestamp | The scheduled date for the review. |
| `checkpointType` | varchar | 'Weekly', 'Day 14', 'Day 30'. |
| `status` | enum | 'Pending', 'Completed', 'Missed'. |
| `notes` | text | Coach's notes from the checkpoint meeting. |
| `conductedById` | int | Foreign key referencing `users.id` for the coach who ran the checkpoint. |
| `createdAt` | timestamp | Record creation timestamp. |

## Capacity Escalations

The `capacity_escalations` table tracks operational, technical, or market issues that suppress agent production but fall outside the direct control of the Agent Success Team.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `id` | int | Primary key, auto-incrementing. |
| `agentId` | int | Foreign key referencing `users.id`. |
| `submittedById` | int | Foreign key referencing `users.id` for the coach raising the issue. |
| `assignedOwnerId` | int | Foreign key referencing `users.id` for the operational staff member responsible for resolution. |
| `relatedSessionId` | int | Foreign key referencing `coaching_sessions.id`. |
| `issueCategory` | varchar | E.g., 'Lead Volume', 'CRM Defect', 'Transaction Support'. |
| `description` | text | Detailed explanation of the barrier. |
| `evidence` | text | Supporting data or examples. |
| `estimatedProductionImpact` | text | The anticipated cost of the issue remaining unresolved. |
| `urgency` | enum | 'Low', 'Medium', 'High', 'Critical'. |
| `status` | enum | 'Draft', 'Submitted', 'Assigned', 'In Progress', 'Waiting for Information', 'Resolved', 'Closed', 'Declined'. |
| `dueDate` | timestamp | The expected resolution deadline. |
| `resolution` | text | Details of how the issue was addressed. |
| `resolutionDate` | timestamp | When the issue was resolved. |
| `coachConfirmation` | boolean | Whether the submitting coach has confirmed the resolution is effective. |
| `createdAt` | timestamp | Record creation timestamp. |
| `updatedAt` | timestamp | Record last update timestamp. |

## Coach-Out Recommendations

The `coach_out_recommendations` table formalizes the process where a coach recommends an agent be removed from the organization due to sustained underperformance or cultural misalignment.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `id` | int | Primary key, auto-incrementing. |
| `agentId` | int | Foreign key referencing `users.id`. |
| `coachOfRecordId` | int | Foreign key referencing `users.id`. |
| `status` | enum | 'Draft', 'Submitted', 'Under Review', 'Approved', 'Declined', 'More Information Required', 'Agent Recovered', 'Completed'. |
| `performanceHistory` | text | Summary of the agent's historical production. |
| `supportProvided` | text | Log of the coaching and resources invested in the agent. |
| `culturalConcerns` | text | Details regarding engagement or behavioral issues. |
| `marketImpact` | text | Assessment of how the agent's removal will affect market coverage. |
| `recommendation` | text | The formal recommendation narrative. |
| `proposedEffectiveDate` | timestamp | The suggested date for termination. |
| `marketOpeningRecommendation` | text | Advice on whether and how to backfill the agent's market. |
| `createdAt` | timestamp | Record creation timestamp. |
| `updatedAt` | timestamp | Record last update timestamp. |

## Coaching Assessments

The `coaching_assessments` table stores personality profiles, work-style assessments, and behavioral test results (such as DISC or Predictive Index) to inform customized coaching approaches.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `id` | int | Primary key, auto-incrementing. |
| `agentId` | int | Foreign key referencing `users.id`. |
| `assessmentType` | varchar | E.g., 'DISC', 'Predictive Index', 'Kolbe'. |
| `assessmentProvider` | varchar | The organization or tool that generated the assessment. |
| `assessmentDate` | timestamp | When the assessment was completed. |
| `fileUrl` | text | S3 URL to the uploaded assessment report document. |
| `fileKey` | varchar | S3 object key for the file. |
| `rawText` | text | Pasted text from an assessment result. |
| `aiSummary` | text | AI-extracted synthesis of the assessment. |
| `isSummaryApproved` | boolean | Indicates whether a coach has verified the AI summary. |
| `communicationStyle` | text | Extracted preferences for communication. |
| `decisionMakingStyle` | text | Extracted approach to making decisions. |
| `motivators` | text | Core drivers for the agent. |
| `stressBehaviors` | text | How the agent reacts under pressure. |
| `preferredCoachingStyle` | text | Recommended approach for coaching this specific agent. |
| `createdAt` | timestamp | Record creation timestamp. |
| `updatedAt` | timestamp | Record last update timestamp. |

## Coaching History Snapshots

The `coaching_history_snapshots` table periodically captures key performance and status metrics. This allows the system to reconstruct an agent's historical trajectory without needing complex point-in-time queries against live operational tables.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `id` | int | Primary key, auto-incrementing. |
| `agentId` | int | Foreign key referencing `users.id`. |
| `snapshotDate` | timestamp | The date the snapshot was captured. |
| `performanceStatus` | varchar | The agent's status band at the time of the snapshot. |
| `trailing90DayUnits` | int | Closed units in the preceding 90 days. |
| `trailing90DayVolume` | decimal | Closed volume in the preceding 90 days. |
| `underContractUnits` | int | Active pipeline units. |
| `underContractVolume` | decimal | Active pipeline volume. |
| `leadVolume` | int | Number of assigned leads. |
| `averageLeadAge` | int | The average age of the agent's leads in days. |
| `overdueTaskCount` | int | Number of overdue CRM tasks. |
| `terminationRate` | decimal | The calculated transaction termination rate. |
| `coachOfRecordId` | int | The assigned primary coach at the time. |
| `fourCDiagnosis` | varchar | The active primary diagnosis at the time. |
| `createdAt` | timestamp | Record creation timestamp. |

## Integration Strategy

The Coaching Hub architecture respects the existing SavvyOS data boundaries. The `agent_goals` table remains the definitive source of truth for all organizational and individual goals. The `users` table continues to govern agent and administrator identities and core profiles. Production data, including `transactions`, `contacts`, `agent_connections`, and `tasks`, will be queried dynamically rather than duplicated into coaching-specific tables. Finally, the new-agent creation flow within `UsersPage.tsx` and the `db.createUser` function will be extended to automatically initialize a `coaching_profiles` record and schedule the mandatory first `coaching_sessions` record.
